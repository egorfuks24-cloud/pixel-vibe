# Script and beat design

Start with the actual tension: “Почему твои сайты выглядят одинаково?” or the concrete change the audience needs to know. Avoid “Сделай красиво”, generic AI-vs-human contrasts and unsupported revolutions.

Each spoken paragraph: concrete trigger → mechanism/evidence → action or implication. Name conditions when claims are conditional. 60–90 seconds is a useful range for a substantial update, not a requirement for every topic. Read the script aloud and time the real recording; word estimates do not establish sync.

On-screen text should identify the object/value, not reproduce the paragraph. Example: voice explains that an agent transfers a task; a task card visibly moves from desktop to phone while progress continues. A limit change needs a dated source and precise eligibility, not an invented half-token diagram.

CTA is a journey: open the relevant artifact → show its useful contents → cursor selects it → profile/channel destination appears. Insert the actual user-supplied link only into a private production project. No fake social proof or promises of free resources unless supplied by the author.

Maintain `voice-script.txt`, `beats.json`, `sources.json` and a private avatar/style control per production project. Do not copy these private files into a skill release.
